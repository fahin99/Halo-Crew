# Shared Render deployment

`render.yaml` provisions one Free Node web service and one Free PostgreSQL database in Oregon. Frontend and API share one HTTPS URL. The shared team workspace uses a passcode gate; this is a hackathon workspace, not an individually authenticated clinical system.

1. Push the project including `render.yaml`, `server/` and `package-lock.json` to GitHub.
2. Render → New → Blueprint → connect `fahin99/Halo-Crew`; select the branch containing this setup.
3. Enter a private `HALO_TEAM_PASSCODE` of at least 12 characters. Never commit it. Share it only with the team.
4. Verify both services show Free ($0), then deploy.
5. Open the generated HTTPS URL, enter the passcode, save a check-in and test a chat. Records live in PostgreSQL, not the disposable web-service filesystem.

Build: `npm ci && npm run build`. Start: `npm start`. Node: 22.16.0. Health check: `/healthz`. Required runtime environment: `NODE_ENV=production`, `DATABASE_URL`, `HALO_TEAM_PASSCODE`, `HALO_SESSION_SECRET` (generated by Render).

Free Render Postgres expires after 30 days. Export records before expiry; choose another database or a paid database later. Free web services sleep after 15 minutes idle and can take about a minute to wake. Open the site before recording a video. Docs: https://render.com/docs/free

Default hosted chat uses rule-based responses. A model is not bundled. Everyone can use the hosted app without installing Ollama, but generative AI needs a shared model endpoint. `HALO_MODEL_URL` can point to a team-controlled Ollama service; keep it private/trusted and set `HALO_LOCAL_MODEL`. Do not expose an unauthenticated model service publicly. No paid cloud API is enabled by default.

This deployment starts with fresh illustrative records. Private `.halo-data` files are never uploaded. Team members access the same astronaut workspace; simultaneous mission edits currently use last-write-wins. Browser fallback data is per-device and is uploaded when server saves resume. Local audio recordings remain browser-only.

Public deployment refuses to start without a database and a sufficiently long passcode. API writes reject cross-origin requests, session cookies are signed/HttpOnly/Secure on hosted mode, and authentication attempts are rate limited. This does not replace production-grade identity, authorization, clinical validation or backups.
